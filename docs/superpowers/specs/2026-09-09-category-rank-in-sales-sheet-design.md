# カテゴリランキングを「売上/日」のラベル行へ移す

2026-09-09

## 背景

カテゴリランキングは現在、独立した「カテゴリランキング」シートに縦=ASIN・横=日付（古い順）で
記録している。売上/日 とは別シートなので、順位と売上・利益を突き合わせるには2枚を並べて
見比べる必要がある。

売上/日 は既に ASIN 1件につき5行のブロック（ASIN行・営業利益・広告経由・粗利益・広告費）を
持ち、日付列を共有している。順位もこの構造に載せれば、1枚で読める。

## 決めたこと

| 論点 | 決定 |
|---|---|
| カテゴリ名の置き場所 | ラベル名に埋め込む（`順位（メガネストラップ）`） |
| 行の位置 | 末尾（広告費の下）・折りたたむ |
| 既存シート | 履歴を売上/日 へ移してから削除する |
| 色 | 向きを反転（最上位=青・最下位=赤）、商品ごとのスケール |

## 行構成

各商品ブロックが5行から**6行**になる。

| # | ラベル | 中身 | 書くのは | 折りたたみ |
|---|---|---|---|---|
| 0 | （ASIN行） | 売上個数。ノートに価格 | `main.py daily` / `today` | 常時表示 |
| 1 | `営業利益` | 数式（粗利益 − 広告費） | 粗利益を書くたび | 常時表示 |
| 2 | `広告経由` | 広告経由の売上個数 | `main.py ads` | たたむ |
| 3 | `粗利益` | 見積または実測 | `daily` / `today` / `finances` | たたむ |
| 4 | `広告費` | その日の広告費 | `main.py ads` | たたむ |
| 5 | `順位（カテゴリ名）` | カテゴリ内の順位 | `main.py ranks` | たたむ |

## ラベル判定を前方一致に拡張する

`bind_label_rows` は商品名列の値がラベル名と**完全一致**する行を探す。順位行は
`順位（メガネストラップ）` のようにカテゴリ名を含むため、このままでは一致しない。

- 順位行だけ「`順位` で始まる行」という前方一致で判定する
- 他の4本は完全一致のまま変えない
- カテゴリが未判明のうちは `順位` だけを置く。順位が付いた時点で `main.py ranks` が
  `順位（カテゴリ名）` へ書き換える

**カテゴリ名の引き継ぎ元がラベル名になる。** 現行はカテゴリランキングシートの D列から
「既に記録したカテゴリ」を読み、そのカテゴリの順位を追い続けている（毎回いちばん良い順位を
採ると日によってカテゴリが入れ替わり時系列が壊れるため）。この読み取り元をラベル名へ移す。

## リポジトリごとの変更

### `data-engineer/download-amazon-data`

- `label_rows.py` — `ROW_LABELS_IN_ORDER` に `順位` を追加。前方一致で順位行を引く関数を足す
- `insert_label_rows.py` — 既存74商品へ6本目を挿入（冪等。既に「期待するラベル列と既存行を
  先頭から突き合わせる」実装なので、途中への挿入に対応済み）
- `apply_row_groups.py` — 折りたたみ範囲が #2〜#5 になる
- `apply_row_heights.py` — 追加した行も半分の高さにする
- `gradient_rules.py` — 順位行に反転グラデーション（商品ごと）

### `marketar/listing-creator`

- `sales_sheet_row.py` — `LABEL_ROWS_IN_ORDER` に `順位` を追加。新商品は6行で挿入される

**ラベルの順序と本数の一致が必要なのは、従来どおりこの2リポジトリだけ。**

### `marketar/category-rank` は `download-amazon-data` へ統合する（2026-09-09 変更）

当初は書き込み先だけを変えて別プロジェクトのまま残す設計だったが、**同じシートの
同じ行を扱う処理を2箇所に分けても得るものが無い**ため統合する。`category-rank` は
一度もコミットされておらず（marketar から見て未追跡）、履歴を失う心配も無い。

- `main.py ranks` サブコマンドにする（`daily` / `ads` / `finances` と並ぶ）
- `label_rows.py` を import できるので、**ラベル判定を再実装しなくてよい**。
  規約を一致させねばならない箇所が増えない
- SP-API の認証は既存の `SpApiAuthenticator` を使う（`category-rank` は独自実装だった）
- カテゴリ名の引き継ぎ元をラベル名にする
- 売上/日 に無い ASIN は対象外（旧シートの「消えた ASIN も末尾に残す」は無くなる）
- `marketar/category-rank/` は削除する
- launchd の `com.automation.category-rank.plist` は `WorkingDirectory` を
  `download-amazon-data` に変え、`main.py ranks` を呼ぶ形に直す

## 日付列は作らない

`main.py ads` と同じ方針にする。

- 既にある日付列にだけ書く。**無い日はスキップし、スキップした日数を出力する**
- 列を作るのは `main.py daily` の責務のまま

売上/日 の日付列は最新が左（newest first）。旧シートは古い順なので、移行時に向きが変わる。

## 変更を入れる順序

ラベルの本数が2リポジトリでずれている間は、新商品だけ順位行を持たない（または余分に持つ）
状態になる。過去にラベル順序がずれて**新商品が永久に空欄**になった事故があるため、順序を守る。

1. `download-amazon-data` の `ROW_LABELS_IN_ORDER` に `順位` を足す
2. `insert_label_rows.py` を実行し、既存74商品へ6本目を挿入する
3. `listing-creator` の `LABEL_ROWS_IN_ORDER` に `順位` を足す（以降の新商品が6行で入る）
4. `apply_row_groups.py` / `apply_row_heights.py` / `apply_gradients.py` を流し直す
5. `category-rank` を `main.py ranks` として統合し、書き込み先を売上/日 へ変える
6. 履歴を移行し、旧シートを削除する

1〜3 の間に新商品が登録されると順位行が無いブロックができるが、`insert_label_rows.py` は
冪等なので後から流せば埋まる。

## 移行

1. 旧シートの履歴を売上/日 の該当日付列へ書き写す1回限りのスクリプトを
   `download-amazon-data/migrate_category_ranks.py` として作る（`--dry-run` を持たせる）
2. `--dry-run` で件数と対象日を確認してから実行する
3. 旧シート（カテゴリランキング）を削除する

売上/日 に列が無い古い日付は移せない。現在の売上/日 は **6/16** まで列がある。
移行が済んだらこのスクリプトは残さない（1回限りの用途で、再実行すると意味を持たない）。

## 色

順位は小さいほど良い。他の行（多いほど良い）と向きが逆になる。

- 最上位=青、最下位=赤。**商品ごとのスケール**（カテゴリの規模が商品ごとに違うため、
  全商品を1つの物差しに載せても大小の意味が薄い）
- 順位が付いていない日は空欄のまま。0 を書かない（未取得と「順位なし」を描き分けられなくなる）
- `apply_gradients.py` が管理する。条件付き書式は 150件 → 約225件に増える

## テスト

- ラベル前方一致 — `順位`・`順位（X）` が引けて、`順位表` のような別ラベルを誤って拾わないこと
- ラベル順序の固定 — 2リポジトリそれぞれのテストで6本の順序を固定する（import できないため）
- 日付列が無い日のスキップと、スキップ日数の出力
- カテゴリ名の引き継ぎ — 既にラベルにカテゴリがあればそのカテゴリの順位を選ぶこと
- 移行スクリプト — 旧シートの表から売上/日 の座標へ正しく写ること

## やらないこと

- 売上/日 に列が無い日付の履歴移行（列を作ってまで遡らない）
- 売上/日 から消えた ASIN の順位履歴の保持
- 旧シートにあった画像列・商品名列の再現（売上/日 に既にある）
